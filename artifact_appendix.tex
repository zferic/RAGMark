\subsection{Abstract}

RAGMark is a modular benchmarking framework for Retrieval-Augmented
Generation (RAG) systems. It decomposes end-to-end RAG execution into
per-query, per-stage measurements (embedding, FAISS retrieval, reranking,
compression, generation) capturing latency, TTFT/decode time, GPU/CPU
power and energy, SM utilization, memory bandwidth, and PCIe transfer,
alongside accuracy metrics (EM, F1, ROUGE-L, retrieval recall). This
artifact reproduces the five characterization cases in the paper (naive,
reranking, compression, combined, iterative) across three Llama-3.2/3
generators, three e5 embedding models, and six open-domain QA datasets
over a Wikipedia-2018 FAISS index.

{\small
\begin{itemize}
  \item {\bf Program: } Dense-retrieval RAG (embed $\to$ FAISS search $\to$ optional rerank/compression $\to$ LLM generation), plus an iterative variant.

\subsection{Experiment workflow}
Each experiment is a sweep config in \texttt{testing\_callsmain\_sweep.py},
run via \texttt{python testing\_callsmain\_sweep.py}:

\begin{itemize}
  \item {\bf Exp. 1 (Fig.~4, reranking): } \texttt{rerank=True}, \texttt{top\_ks=[0,1,3,5,10]}, all 3 generators $\times$ 6 datasets.
  \item {\bf Exp. 2 (Fig.~5, compression): } \texttt{compress=True}, \texttt{compress\_method="llmlingua2"}, \texttt{top\_ks=[1,3,5,10]}, \texttt{compress\_rates=[0.2,0.4,0.6,0.8]}.
  \item {\bf Exp. 3 (Fig.~9, trade-off): } naive pipeline (\texttt{rerank=False}, \texttt{compress=False}), \texttt{top\_ks=[0,1,3,5,10]}, all 3 generators.
\end{itemize}

Existing outputs are skipped, so interrupted sweeps resume cleanly.
